# Compa Brand Kit

This directory is the complete editable Compa identity kit. It is
self-contained for review and works offline with system font fallbacks. Read
[`BRAND.md`](BRAND.md) before adapting an asset.
[`provenance.json`](provenance.json) lists every file that uses the kit, and
the surfaces that don't use it yet.

SVG, JSON, CSS, HTML, JavaScript, and Markdown files are the editable sources.
Do not edit a PNG or ICO as a master. The kit intentionally includes no font
files, remote resources, asset hashes, lock manifests, or generated dependency
directories.

## Review locally

From the repository root:

```powershell
node brand/check.mjs
Start-Process (Resolve-Path -LiteralPath 'brand/preview.html')
```

The preview uses only relative local assets. No server, install, product binary,
or network request is required.

## Rebuild the rasters and consumer copies

`export.mjs` renders every raster from its SVG master with the Chromium that
Playwright installs for the frontend, packs the ICO files, and writes the
consumer SVG copies. It needs only Node built-ins and `@playwright/test` from
`web/frontend/node_modules`. From the repository root:

```powershell
# Once: the frontend's dependencies and Playwright's Chromium.
Push-Location web/frontend
pnpm install --frozen-lockfile
npx playwright install chromium
Pop-Location

node brand/export.mjs
node brand/check.mjs
```

| Output | Master | Pixels | Background |
|---|---|---|---|
| `brand/og/og-default.png`, `docs/og.png` | `og/og-default.svg` | 1200 x 630 | Opaque |
| `web/frontend/public/favicon.ico` | `icons/favicon.svg` | 16, 32, 48 | Transparent corners |
| `web/frontend/public/favicon-96x96.png` | `icons/favicon.svg` | 96 | Transparent corners |
| `web/frontend/public/apple-touch-icon.png` | `icons/maskable.svg` | 180 | Opaque, full bleed; iOS rounds it |
| `web/frontend/public/web-app-manifest-192x192.png` | `icons/icon-192.svg` | 192 | Transparent corners |
| `web/frontend/public/web-app-manifest-512x512.png` | `icons/icon-512.svg` | 512 | Transparent corners |
| `web/backend/icon.ico` | `icons/favicon.svg`, and `icons/app-icon.svg` for 256 | 16, 24, 32, 48, 64, 256 | Transparent corners |
| `web/backend/icon.png` | `icons/app-icon.svg` | 512 | Transparent corners |
| `web/frontend/public/favicon.svg` | `icons/favicon.svg` | Copy | As the master |
| `web/frontend/public/compa-mark.svg`, `docs/compa-mark.svg` | `logos/mark.svg` | Copy | As the master |
| `web/frontend/public/compa-logo.svg`, `docs/compa-logo.svg` | `logos/lockup.svg` | Copy | As the master |

Each master opens as its own document in a headless viewport of exactly the
output size at device scale factor 1 and is captured as a PNG, with the page
background left transparent where the tile has transparent corners. Each ICO
file holds one PNG-compressed RGBA entry per size, smallest first. Consumer SVG
copies add only an intrinsic `width` and `height` and a generated-file comment.

Browser tabs, taskbars, and trays can be light or dark, so their small sizes use
the favicon tile: the inverse mark on Core Night stays visible on both. Windows
loads the tray icon's 32, 48, or 64 entry for the display scale and shrinks it
into the notification area.

The output is deterministic for a given Chromium build and font set; the script
prints a SHA-256 for every file it writes, so two runs are easy to compare. Only
the OG card contains text, set in Arial and a system monospace font, so rebuild
it on a machine that has those fonts.

## Manual exports

- Export SVGs in sRGB without gradients, filters, glow, drop shadow, or added
  metadata.
- Preserve each supplied viewBox and the exact mark paths and core rectangle.
- Keep transparent logo backgrounds transparent. Only icon files include the
  Core Night tile.
- For a typography-frozen vendor handoff, convert wordmark text to outlines in a
  copy and retain the live-text SVG here as the master.
- Rasterize the OG image at exactly 1200 x 630. Rasterize icons at their named
  dimensions; inspect 16, 32, and 64 px favicon use separately.
- Do not upscale a raster to create another deliverable. Render again from SVG.

## Validation

Run these checks from the repository root:

```powershell
node brand/check.mjs
python -c "from pathlib import Path; import xml.etree.ElementTree as ET; files=list(Path('brand').rglob('*.svg')); [ET.parse(p) for p in files]; print(f'parsed {len(files)} SVG files')"
node -e "const fs=require('node:fs'); for(const p of ['brand/tokens.json','brand/provenance.json']) JSON.parse(fs.readFileSync(p,'utf8')); console.log('parsed brand JSON')"
git diff --check
```

Besides the kit itself, `check.mjs` verifies the adopted consumers: the SVG
copies match their masters, every raster and ICO entry has its planned size, the
manifest and theme colors match the tokens, and the app logo carries the fixed
geometry. After changing a consumer, also run the app's own checks: `npx tsc -b`,
`pnpm run lint`, `pnpm test`, and `pnpm run build` from `web/frontend`, and
`go build -tags goolm,stdjson ./web/backend` from the repository root.

The root `LICENSE` and `NOTICE` remain the authority for product software and
upstream software attribution.
